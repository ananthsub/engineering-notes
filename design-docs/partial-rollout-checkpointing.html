Architecture decision · 1 September 2026

Partial-rollout checkpointing for NeMo-RL and NeMo Gym

owner ansubramania · Gym draft stack at a2e92b237 · companion NeMo-RL integration boundary · self-contained HTML, inline CSS/JS/SVG

The eight-PR Gym draft stack implements the server participants needed to pause policy, agent, and stateful resources traffic; save a consistent boundary for each participant; restore that boundary as attempt N+1; and reject late work from attempt N. It does not yet implement the training controller that coordinates those participants or the durable TransferQueue checkpoint. Gym preserves model-lineage coordinates, agent turns, and resources revisions; the remaining training-framework work must join those records to durable token rows and publish the global checkpoint.

Requirements for a recoverable checkpoint

These requirements define when a checkpoint is safe to publish and restore. The walkthrough shows where each requirement affects normal execution, checkpoint preparation, saving, and recovery.

System constraints

  • Gym must commit before the global checkpoint is published. A slow rollout therefore cannot block checkpointing indefinitely.
  • Durable token state remains a training-framework responsibility. The Gym draft stores lineage and staging coordinates, not token, mask, or log-probability arrays. A production checkpoint may be published only after the controller has made the referenced TransferQueue rows durable and has verified the join. That controller and actual queue durability are not part of PRs #2939–#2946.
  • Recovery starts from the latest published checkpoint. Gym keeps server state in memory and serializes it only during a checkpoint commit. After an unplanned crash, NeMo-RL re-dispatches any later in-flight work from its input.
  • One leased SingleController dispatches rollouts and coordinates checkpoints. A second controller cannot run concurrently.
  • The design must support large live execution sets. Shared-filesystem metadata operations cannot grow linearly with the number of rollouts.

Identity

A rollout keeps one identity across attempts.

NeMo-RL assigns rollout_id before dispatch and preserves it across retries and restores. Each fresh dispatch or restore increments _ng_attempt_index. The attempt-qualified path (…-aN) identifies captured transport data, not the logical rollout. Every artifact, control call, and result carries the rollout ID and attempt index as separate fields.

Servers reject stale attempts.

A model, resources, or runtime mutation receives HTTP 409 when it carries an obsolete attempt index. Restore may add tombstones for abandoned call roots, but it cannot remove or reassign them. Final attribution ignores every tombstoned root.

Admission and quiescence

Closing a gate and testing admission happen atomically.

The AdmissionLimiter grants a capacity permit only while the gate accepts work. Closing the gate atomically rejects or parks new callers. A caller waiting for capacity holds no permit and does not count as in flight. An admitted request remains in flight until its response and required custody updates are durable.

Only policy model servers pause in the first milestone.

Token-capture checkpointing first closes admission only on policy model-server instances backed by NeMo-RL generation workers. Stateless resources servers and verifiers retain no checkpoint state and do not need an admission API. Stateful-resources support later closes admission on those resources-server instances as well. Judge and simulator model-server instances remain open so accepted tools and verifiers can finish. Startup validation rejects environment traffic that targets a policy instance.

A model-server pause must cover every FastAPI worker process.

A pause request routed to one Uvicorn worker cannot close admission for the other workers that share the service port. The PR stack implements and tests a service-level coordinator protocol over a Unix-domain socket. Workers apply coordinator state and report acknowledgements plus local in-flight counts. The coordinator reports paused only after every expected worker has acknowledged the checkpoint ID and the summed count is zero. Production startup and control-URL routing are not wired yet, so a configured multi-worker server reports unmanaged and NeMo-RL must refuse checkpointing through it. Single-worker servers are the supported first integration.

Prepare parks whitebox agents before it closes dependent servers.

POST /ng-control/v1/agent-checkpoint/prepare changes active runs to park_requested. Each run finishes its current turn, records an AgentBoundaryRecord, and blocks on an in-memory event. NeMo-RL closes policy-model admission and prepares resources state only after the agent prepare call succeeds. Judge and simulator model instances remain open while the current turn finishes. This order avoids using a 409 checkpoint_parked response as normal whitebox control flow.

Resources mutations finish before state export.

The resources middleware serializes mutations for each rollout attempt with an asyncio.Lock. Resources prepare closes admission, acquires each live session's lock, and exports that session after any accepted mutation releases the lock. New mutations receive 409 resources_admission_closed. The first integration does not propagate admission leases or expose separate resources-admission routes.

The controller decides what happens to unfinished rollouts.

The Gym routes expose blockers and provide attempt-specific model abort, agent retirement, and resources retirement. Resources retirement is checkpoint-fenced and waits for that execution's mutation lock before it removes adapter state and the prepared snapshot. A future controller must decide whether all participant state for a straggler can be discarded. If an external effect cannot be rolled back or acknowledged, the controller must abort the global checkpoint rather than publish an incomplete cut.

Ordering

Generation workers stay available during prepare.

Accepted generations must finish staging their output before Gym can drain. Pausing workers earlier would deadlock prepare. NeMo-RL may pause, checkpoint, or refit workers only after Gym commits and before the final resume.

The future controller must finish finalizers before saving TransferQueue.

Pausing Gym does not stop an RL-side finalizer that is already writing token rows. The training-framework integration must wait for those writes, publish a completed group before clearing staged rows, and then save the queue. This ordering is not implemented by the Gym stack.

Each manifest is written last.

A component writes payloads to temporary names, flushes them, and renames them before writing its manifest. The actor verifies every component digest before writing gym/manifest.json. The SingleController writes training_info.json last, renames the checkpoint atomically, and flushes the parent directory. A committed participant directory never changes.

One explicit call resumes work in dependency order.

Prepare, commit, and restore leave Gym paused. After the checkpoint is published and generation workers pass validation, NemoGym.resume opens resources admission, policy model admission, relays and runtimes, parked loops, and dispatch in that order.

Durability and publication

TransferQueue needs its own durable snapshot contract.

The intended training checkpoint uses a fresh content-addressed path and restores it by the digest recorded in the global checkpoint. The Gym stack neither defines nor exercises that persistence operation; it only stores the coordinates that the controller must validate against the restored queue.

Gym components publish immutable manifests after their payloads.

The current draft writes one JSON payload per parked agent boundary or resources snapshot and copies token-free lineage files, then writes a digest-bearing manifest last. This makes torn writes and corrupt restore input detectable. It is not the final format for large live rollout sets. Archive shards with a member index can replace the per-rollout files later without changing the checkpoint APIs or state machine.

Control operations are idempotent and fenced.

Every actor method and control endpoint carries checkpoint_id and an absolute deadline. Repeating a phase for the same checkpoint returns the recorded result. A stale checkpoint ID cannot reopen traffic or replace files. A short-held mutex in the NemoGym actor protects checkpoint phase changes and snapshots of the live-execution registry. It prevents two checkpoint IDs from preparing concurrently, prevents commit, abort, restore, and resume from racing, and rejects invalid transitions such as commit before prepared. The actor releases the mutex before waiting for servers to drain so checkpoint_progress and abort_checkpoint remain callable during a long prepare.

Restore

NeMo-RL chooses one recovery action for each execution.

An execution is already complete, resumes from an agent boundary, resumes from a full runtime snapshot, or starts again from its input. An execution marked transferred_to_rl cannot also have a continuation. The restored NeMo-RL registry decides whether work completed or failed. Gym does not make that decision.

Gym restores participants paused; the controller verifies the full join.

Each participant restores attempt-N state as attempt N+1 and remains closed until an explicit resume. The model participant rejects a non-fresh ledger namespace. The resources participant requires a fresh process that has not served stateful traffic. The agent participant installs continuations without starting /run. The future controller must still verify each agent boundary against its model lineage, resources revision, and restored TransferQueue rows before dispatch.

An opaque harness requires a full runtime snapshot.

A filesystem snapshot, sandbox identifier, or provider descriptor cannot restore an opaque harness by itself. A resumable snapshot includes the harness process tree and memory, the egress relay's pending requests and cached responses, and a provider compatibility fingerprint. At the prepare deadline, the runtime may freeze a forwarded but unfinished request as pending reissue. Restore tombstones the abandoned server-side call and sends a new request through the relay.

A rollout does not have one global state enum

The implementation deliberately separates three kinds of state. NeMo-RL owns whether a logical rollout still needs a result. The agent server owns where one /run attempt is executing. Each Gym server owns the phase of the current checkpoint transaction. Treating these as one enum would create impossible combinations: for example, an agent can be running after boundary 4 while boundary 4 is already safe to save, and a resources server can be checkpoint-prepared while the model server is still draining an accepted generation.

Logical rollout and attempt identity

rollout_id identifies the logical work across failures. attempt_index identifies one execution of that work. Restore never reactivates attempt N. It installs state for attempt N+1 and tombstones attempt N, so delayed HTTP requests from the old process receive 409 stale_attempt instead of mutating restored state.

Agent execution state

A boundary is the completed state after a whole agent turn, not a separate execution state. While the agent is running turn 5, its boundary for turn 4 may remain available as the latest safe rollback point. Prepare changes running to park_requested. The agent finishes the current operation and commits the next boundary before it blocks on an in-memory event. No file is polled on each turn.

The participant reports whether each parked execution has a committed boundary. Both a parked execution without a boundary and a completed result that the training framework has not durably acknowledged make ready_to_commit false. A boundary does not make every parked state publishable, and completion alone does not transfer ownership of the result.

If the deadline expires while an agent is still between boundaries, prepare fails without caching a successful result. Retirement cancels both the outer /run task and the active inner handler task, including a handler blocked while parking at a boundary. Retirement is not durable result acknowledgement: a completed-but-unacknowledged execution refuses retirement and continues to block publication. Failed executions discard cached boundary, continuation, and result payloads, remove the live execution, and tombstone that attempt.

Checkpoint phase and admission state

The control fence is per server process and per checkpoint ID. It prevents a stale or concurrent controller from committing, restoring, or resuming the wrong transaction. Repeating the same successful operation returns its recorded result. Most failed operations return to their entry phase. Model restore is deliberately different: a failure leaves both the limiter and the control fence in restore_failed_paused, so status remains observable and the same restore can be retried or explicitly resumed without admitting traffic by accident.

Admission is a separate state machine. The policy model server changes from accepting to draining when prepare closes its gate. Requests already admitted remain counted until their complete HTTP response has been sent and token custody has been recorded. When that count reaches zero, the limiter changes to paused. New requests receive 409 checkpoint_parked. Resume reopens admission after commit or restore.

What the current Gym draft guarantees

The model, agent, and resources participants can independently preserve a compatible attempt-N cut and install it for attempt N+1 while traffic remains paused. Their manifests are separated by model server, agent instance, and resources server inside one controller-supplied directory. The production guarantee still depends on a controller that checks all three manifests and the matching TransferQueue snapshot before publishing one global checkpoint.

The Python implementation is intentionally internal

The checkpoint modules in PRs #2940–#2946 live under nemo_gym._checkpoint. The leading underscore marks this as an experimental implementation rather than a supported public import surface. Gym servers use these modules internally while the protocol, controller integration, and storage format continue to evolve. A later stabilization change can expose a public package after those contracts are ready for compatibility guarantees.

Work remaining outside the Gym draft stack

  • Implement the NeMo-RL controller state machine, live-execution registry, durable result acknowledgement, participant ordering, global publication marker, restore reconciliation, and explicit resume sequence.
  • Implement actual TransferQueue checkpoint durability and verify that every staging coordinate named by restored model lineage exists before a continuation starts.
  • Wire the multi-worker coordinator into Gym process startup and route one authenticated control URL per server instance. Until then, require num_workers=1.
  • Aggregate model-ledger commit and restore across the same worker set. The current coordinator protocol covers admission state and in-flight counts only.
  • Apply deadline_ts inside commit, restore, and resume operations. Those request models carry the deadline today, but only prepare and model-drain waits actively enforce it.
  • Pack per-rollout payloads into bounded archive shards before using the format at very large rollout counts.

How the components share checkpoint ownership

The intended SingleController owns the global checkpoint transaction, but that controller integration is not in the Gym draft stack. The implemented Gym side gives each server a participant with authenticated control routes. The agent server owns each /run loop. The policy model server owns admission and token-free lineage. Stateful resources servers own environment sessions and revisions. A future NeMo-RL NemoGym actor must order those routes, make the referenced TransferQueue rows durable, and publish the global checkpoint.

Normal rollout execution records restorable state

Each component records the state it already owns during normal execution. The actor registers executions, the model server records token custody, generation workers stage tokens, and resources servers retain sessions. Checkpointing does not add per-rollout filesystem writes during this phase. Use the controls below to follow the calls in execution order. When the walkthrough has focus, the left and right arrow keys change steps.

Prepare stops new work and reaches a recoverable boundary

The intended NeMo-RL flow first stops new /run dispatch and asks each whitebox agent server to prepare. Active runs finish their current turn and park after committing a boundary. It then pauses policy-model admission and prepares resources state. The Gym routes implement these participant operations; the actor that orders them is still required. If an agent misses the deadline or reports an unsafe parked or completed state, prepare fails. A controller may retire a restart-safe attempt and retry, but Gym does not silently discard it.

Save publishes only a complete checkpoint

The Gym draft accepts one controller-owned directory and writes the frozen model, agent, and resources state into separate namespaces beneath it. Each component publishes a digest-bearing manifest last and remains paused until explicit resume. The remaining controller work must stop its rollout registry and TransferQueue writers, invoke those commits, save the actual queue, validate every artifact, and publish the global checkpoint. The current Gym format uses per-rollout JSON and lineage files; shard packing is a later scalability optimization.

Restore verifies each continuation before dispatch

Replacement Gym processes restore model lineage, resources sessions, and agent continuations while admission remains closed. The resources process must be fresh, and every participant requires a separate explicit resume. The first resumed policy call carries the verified attempt-N source capture key and parent model-call ID exactly once. That lookup copies the complete staging coordinates for the parent into attempt N+1. Later calls omit the cross-attempt headers and resolve their parent within attempt N+1.

The production-route test joins all Gym participants

The top PR, Gym #2946, contains tests/unit_tests/test_checkpoint_e2e.py. The test uses the production participant installers and authenticated control routes for one checkpoint and recovery cycle. It supplies a small in-process controller sequence so the test can exercise cross-component behavior without claiming that NeMo-RL orchestration is implemented.

Behavior exercised by the test

  1. Agent prepare rejects a parked execution with no committed boundary and a completed result with no durable training-framework acknowledgement.
  2. A restart-safe straggler is retired from the agent and resources participants and aborted in model admission. Its model lineage is excluded from the committed cut.
  3. The model, agent, and resources participants write three separate manifests beneath the same controller directory. The model manifest is namespaced by server name; the agent manifest is namespaced by a stable hash of the configured instance name; the resources manifest is namespaced by server name.
  4. Fresh replacement processes restore the surviving rollout as attempt N+1 and reject model, agent, and resources traffic before explicit resume.
  5. After resume, the resources revision and state are available under N+1. The first policy call receives the attempt-N source capture key and parent call. Its copied lineage retains the parent's staging key, weight version, lengths, digests, mode, staging chain, chain hash, and cumulative hash.
  6. The relay headers are consumed once. The next policy call carries no attempt-N parent headers and resolves to the first call recorded within N+1.

Boundary of this end-to-end test

The test simulates controller ordering with direct route calls. It does not implement the NeMo-RL SingleController or NemoGym actor. It records representative staging coordinates in the lineage store, but it does not save, restore, or validate an actual TransferQueue snapshot. Those two integrations remain outside the Gym PR stack.

Why component-owned boundaries are the default

The central constraint is not writing bytes to disk. It is choosing a point where the agent conversation, resources state, model-call lineage, and token rows describe the same completed work. The Gym draft APIs let each server finish the operation it owns and freeze its local state. The remaining NeMo-RL integration must coordinate those participants and verify the cross-component join without importing each environment's private representation.

Cleanup preserves fences while releasing failed work

Failed agent executions clear their boundary, continuation, result, and task references before leaving the live map. Resources lock entries are pruned after their final user releases them when no live revision remains. Tombstones remain separate so delayed attempt-N traffic is still rejected. Completed agent results intentionally remain cached because the stack has no durable training-framework acknowledgement route yet; that missing acknowledgement is the remaining ownership boundary.

Prefix custody is common, but prefix delivery differs by inference backend

Hashes and lineage keys identify and authenticate a token prefix, but they are not an inference prompt. A backend must obtain the actual token IDs before it can prefill the next model call. The vLLM capture path can send a TransferQueue staging chain to a generation worker because that worker can read the referenced rows. The Megatron Inference integration in Gym #2823 cannot do that today, so its capture handler sends required_prefix_token_ids inline.

Make the delivery representation explicit

prefix: InlinePrefix | StagedPrefix | None

InlinePrefix:
  kind: "inline"
  token_ids: [...]
  cumulative_hash: "..."

StagedPrefix:
  kind: "staged"
  staging_chain: [...]
  cumulative_hash: "..."

A root call has no prefix. A child call has exactly one representation. An inline prefix carries exactly prev_len token IDs and no staging chain. A staged prefix carries a nonempty staging chain and no token array. Both retain the same parent_call_id, prev_len, parent chain hash, and cumulative token hash. This replaces the current implicit contract in CaptureAdmission, where required_prefix_token_ids and staging_chain are independent optional fields and can both be populated.

Do not store both forms as competing custody records

Persisting cumulative token arrays and a staging chain for the same prefix creates two possible sources of truth. The forms can disagree, and repeatedly storing the cumulative array makes storage grow quadratically across a long multi-turn rollout. The durable ledger should record one authoritative custody location. Prefix delivery can then adapt that location to the backend: vLLM dereferences a staged chain itself, while an RL-side prefix materializer can fetch the same chain and send inline tokens to Megatron Inference.

Megatron checkpoint recovery needs more than the schema change

The explicit prefix union is a localized wire-contract cleanup. Continuing an unfinished Megatron generation is a larger cross-repository change. Megatron Inference needs a cut operation for an active request rather than only a finished-request ledger record. NeMo-RL must stage that cut in TransferQueue before the global checkpoint is published. During restore, either Megatron gains a TransferQueue prefix source or NeMo-RL materializes the staged prefix and sends it inline before prefill. The current rollout-end flush_token_capture() path does not provide this checkpoint-time behavior.

Why this approach fits Gym

Gym already separates ownership across agent, model, and resources servers. The participant approach follows that boundary: shared infrastructure supplies identity, fencing, admission, manifest-last publication, and stale-attempt rejection, while each stateful implementation supplies only its codec and turn boundary. It preserves cheap drain-or-restart fallbacks, adds continuation one component at a time, and lets NeMo-RL coordinate the global checkpoint without importing environment-specific logic. The cost is more protocol surface and careful failure ordering. That cost is justified for expensive, long-running, stateful whitebox rollouts. Short stateless rollouts and opaque unsupported harnesses should continue to drain or restart.

Assumptions the controller must enforce

  • Cross-component validation is an RL responsibility. Gym records last_committed_model_call_id, complete model staging coordinates, and resource_state_revisions, but it does not join them to a durable TransferQueue snapshot or choose the final recovery disposition.
  • The global commit marker is outside Gym. One Gym component can commit before another fails. The SingleController must select a checkpoint only after every required participant manifest validates.
  • Deadlines use synchronized wall clocks. Every request carries one absolute deadline_ts. Excessive clock skew can shorten or extend a participant's effective budget.
  • Only bounded waits enforce the deadline in the current stack. Prepare and model-drain paths consult deadline_ts. Component commit, restore, and resume still need explicit checks around potentially long filesystem or backend operations.
  • Checkpoint paths identify the same storage namespace. Server processes must see the controller-provided directory consistently. A remote or differently mounted worker cannot interpret a process-local path.
  • An unsuccessful mutation must not hide a committed effect. The resources middleware increments revisions only for successful HTTP responses. An environment that mutates state and then returns an error needs rollback or an explicit outcome record before it can claim continuation support.
  • Atomic resources activation is an environment callback contract. The shared participant passes the complete replacement set to restore_checkpoint_states. Each adapter must validate everything before replacing live maps; the framework cannot make a sequence of arbitrary environment mutations atomic on its own.
  • Completed results need a shared acknowledgement contract. The agent participant retains and reports completed-but-unacknowledged results, and retirement refuses to stand in for acknowledgement. NeMo-RL must durably accept the result before Gym can remove it from the recoverable live set. Resources tombstone cleanup depends on the same shared ownership decision.
  • Capability discovery is necessary but not sufficient. A custom whitebox agent must actually call commit_boundary; inheriting checkpoint routes without emitting boundaries does not make it resumable.

APIs required to coordinate the checkpoint

The checkpoint API is delivered in four additive milestones. Each milestone produces a useful recovery guarantee and becomes the foundation for the next one. Exists means the behavior is on the main branch. PR means the Gym checkpoint stack ending at #2946 contains the behavior. New means it still needs to be built.

The SingleController calls the NemoGym actor. The actor calls Gym control endpoints, and agents call resources servers. This boundary keeps checkpoint coordination out of individual rollout implementations.

Scope of the current Gym stack

PRs #2939 through #2946 implement stable execution identity, shared fenced control contracts, single-worker policy-model admission, the multi-worker coordinator protocol and test harness, namespaced model-ledger commit and restore, whitebox agent boundaries, resources snapshots, the Gymnasium base and initial stateful adapters, and the production-route end-to-end test in #2946. The experimental checkpoint modules are grouped under nemo_gym._checkpoint; no public Python import contract is claimed. Companion NeMo-RL orchestration and actual TransferQueue checkpoint durability are intentionally outside this stack. Production launcher wiring for the multi-worker coordinator and blackbox runtime snapshots are also outside it.

Milestone 1 — Preserve captured tokens for stateless rollouts

This milestone supports direct-answer or otherwise restartable rollouts whose resources server and verifier retain no session state. It preserves exact token rows and their model-call lineage after they reach durable custody. It does not resume inside an unfinished generation and it does not serialize an agent loop. A rollout that has not returned its result to NeMo-RL at the checkpoint boundary starts again from its original input after restore.

How each Gym server can recover

The shared APIs are not enough for servers that keep rollout state. Each concrete server needs one recovery disposition:

  • no_op: the server has no checkpoint state and needs only shared admission middleware.
  • export_restore: the server implements versioned state encoding and restoration hooks.
  • reconnect_descriptor: the server reconnects to sandbox-backed state through a ConnectableProvider.
  • restart_only: the server cannot restore a valid continuation, so the rollout starts again from its input.
  • full_runtime_snapshot: the provider captures and restores an opaque agent runtime.

A resources server that does not opt into session-state checkpointing is not represented by a resources manifest. The future controller must treat it as stateless or restart-only based on an explicit capability, rather than infer safety from the absence of hooks.

Several servers still need explicit compatibility checks. speed_bench measures wall-clock windows, so pausing changes its metric and should make the server report that it cannot checkpoint. code_gen and verifiers_agent keep mutable global state across sessions. ns_tools runs a shared sidecar process. longmt_eval and wmt_translation require their Ray actor pools on the restore host. Recommended implementation order

  1. gymnasium base-class hook — one change covers the whole gymnasium family and gives non-exportable subclasses a declaration point.
  2. swebench reconnect descriptor — unblocks the SWE rollout class end to end; litmus_agent follows the same pattern.
  3. toolsandbox codec — serialize its DataFrames and role-scoped state by following the existing workplace_assistant pattern.
  4. The blackbox cluster (anyswe, anyterminal, harbor, osworld, swe_agents) — full-runtime snapshot through one provider, restart_only until then.
  5. The CLI-agent cluster (8 agents, one shape) — a single workspace-archive + session-file strategy later; restart_only now.
  6. aviary reconnect-by-env-id with its upstream server.

Integration work after the Gym stack

The following milestones describe remaining cross-repository work. They are not additional claims about what PRs #2939–#2946 already implement.

Remaining milestone 1 — Controller and token-store publication

  1. Add the NemoGym live-execution registry, durable result acknowledgement, and checkpoint participant methods.
  2. Connect worker-owned token staging, model custody lineage, terminal attribution, and the NeMo-RL finalizer.
  3. Make inline and staged prefix delivery explicit and mutually exclusive. Preserve one integrity contract while allowing vLLM to fetch a staging chain and Megatron Inference to receive inline tokens.
  4. For Megatron checkpoint support, add an active-prefix cut and checkpoint-time TransferQueue flush. The existing rollout-end deferred-ledger flush is not a checkpoint boundary.
  5. Make the real TransferQueue snapshot durable after RL-side finalizers quiesce, then reconcile restored model manifests against the restored staging rows.
  6. Publish a global controller marker only after every required Gym manifest and training-framework artifact validates.

Exit condition: completed captured rollouts and groups survive a controller restart with the same exact token rows. An unfinished rollout restarts from input without selecting staged rows from its abandoned attempt.

Remaining milestone 2 — Controller-selected whitebox continuation

  1. Call the implemented agent prepare, commit, restore, retirement, and resume routes in dependency order.
  2. Do not publish while agent status reports parked-without-boundary or completed-unacknowledged executions.
  3. Reconcile each boundary's last model-call ID and resources revisions with the model manifest, resources manifests, and restored TransferQueue rows before making the continuation runnable.

Exit condition: a supported multi-turn whitebox agent resumes between operations with its conversation and control-flow state intact while using a stateless resources server.

Remaining milestone 3 — Stateful resources reconciliation

  1. Start restore-expected resources servers as fresh paused processes and pass their namespaced manifests to the implemented restore routes.
  2. Verify the agent boundary's recorded resources revision before dispatch and define the shared acknowledgement that permits completed-session tombstone cleanup.
  3. Require nested judge and simulator calls to use auxiliary model instances that remain available during policy-model prepare.
  4. Apply the deadline policy only to sessions whose implementation declares that its partial state and external effects can be discarded safely.

Exit condition: a whitebox agent and its logical environment session restore under a replacement attempt. The resources state is installed before the agent resumes.

Milestone 4 — Blackbox runtime continuation

  1. Add a checkpoint-aware egress relay inside the runtime boundary.
  2. Add one runtime provider that can freeze and restore the complete harness process tree and memory.
  3. Capture pending requests and cached responses, then remap endpoints and attempt identity before resume.
  4. Keep providers without full-runtime support explicitly restart_only.

Exit condition: an opaque harness resumes from a full runtime snapshot without losing, duplicating, or misattributing a model or resources request.

Validation applied at every milestone

Inject crashes before and after every manifest publication boundary. Exercise stale checkpoint IDs, prepare deadlines, and worker loss. Verify that a continuation is selected only when its agent, resources, model-lineage, and TransferQueue links required by that milestone are all present.

Known limitations of the current draft

  • No NeMo-RL controller calls these routes, acknowledges completed results, reconciles participant manifests, or publishes a global checkpoint yet.
  • The end-to-end test simulates controller ordering and token staging coordinates. It does not exercise real TransferQueue save and restore.
  • Multi-worker admission coordination has a protocol and test harness, but production launcher and control-URL wiring are absent. Model-ledger aggregation across those workers is also absent.
  • Commit, restore, and resume carry deadlines but do not bound every filesystem or adapter callback with them.
  • The artifact format writes individual rollout files. A bounded archive format is still needed before adopting it for large live sets.
  • Opaque blackbox harnesses still need a full runtime snapshot and egress relay. Descriptor reconnect alone cannot preserve process memory or pending calls.
