Architecture decision · 1 September 2026

Partial-rollout checkpointing for NeMo-RL and NeMo Gym

owner ansubramania · Gym API prototype and companion NeMo-RL design · self-contained HTML, inline CSS/JS/SVG

The Gym PR stack exposes the server-side APIs needed to pause new work, preserve completed agent turns and environment mutations, commit component-owned state, restore it under a replacement attempt, and reject late requests from the abandoned attempt. Companion NeMo-RL changes will assign durable rollout identities and call these APIs in checkpoint order. Generated tokens remain in TransferQueue; Gym stores only the references needed to join an agent boundary to those token rows.

Requirements for a recoverable checkpoint

These requirements define when a checkpoint is safe to publish and restore. The walkthrough shows where each requirement affects normal execution, checkpoint preparation, saving, and recovery.

System constraints

  • Gym must commit before the global checkpoint is published. A slow rollout therefore cannot block checkpointing indefinitely.
  • Generated data remains in TransferQueue. Generation workers synchronously stage token, mask, and log-probability deltas before acknowledging each call. The Gym model server records token-free references and never receives token arrays.
  • Recovery starts from the latest published checkpoint. Gym keeps server state in memory and serializes it only during a checkpoint commit. After an unplanned crash, NeMo-RL re-dispatches any later in-flight work from its input.
  • One leased SingleController dispatches rollouts and coordinates checkpoints. A second controller cannot run concurrently.
  • The design must support tens of thousands of live executions. Shared-filesystem metadata operations cannot grow linearly with the number of rollouts.

Identity

A rollout keeps one identity across attempts.

NeMo-RL assigns rollout_id before dispatch and preserves it across retries and restores. Each fresh dispatch or restore increments _ng_attempt_index. The attempt-qualified path (…-aN) identifies captured transport data, not the logical rollout. Every artifact, control call, and result carries the rollout ID and attempt index as separate fields.

Servers reject stale attempts.

A model, resources, or runtime mutation receives HTTP 409 when it carries an obsolete attempt index. Restore may add tombstones for abandoned call roots, but it cannot remove or reassign them. Final attribution ignores every tombstoned root.

Admission and quiescence

Closing a gate and testing admission happen atomically.

The AdmissionLimiter grants a capacity permit only while the gate accepts work. Closing the gate atomically rejects or parks new callers. A caller waiting for capacity holds no permit and does not count as in flight. An admitted request remains in flight until its response and required custody updates are durable.

Only policy model servers pause in the first milestone.

Token-capture checkpointing first closes admission only on policy model-server instances backed by NeMo-RL generation workers. Stateless resources servers and verifiers retain no checkpoint state and do not need an admission API. Stateful-resources support later closes admission on those resources-server instances as well. Judge and simulator model-server instances remain open so accepted tools and verifiers can finish. Startup validation rejects environment traffic that targets a policy instance.

A model-server pause must cover every FastAPI worker process.

A pause request routed to one Uvicorn worker cannot close admission for the other workers that share the service port. The PR stack implements and tests a service-level coordinator protocol over a Unix-domain socket. Workers apply coordinator state and report acknowledgements plus local in-flight counts. The coordinator reports paused only after every expected worker has acknowledged the checkpoint ID and the summed count is zero. Production startup and control-URL routing are not wired yet, so a configured multi-worker server reports unmanaged and NeMo-RL must refuse checkpointing through it. Single-worker servers are the supported first integration.

Prepare parks whitebox agents before it closes dependent servers.

POST /ng-control/v1/agent-checkpoint/prepare changes active runs to park_requested. Each run finishes its current turn, records an AgentBoundaryRecord, and blocks on an in-memory event. NeMo-RL closes policy-model admission and prepares resources state only after the agent prepare call succeeds. Judge and simulator model instances remain open while the current turn finishes. This order avoids using a 409 checkpoint_parked response as normal whitebox control flow.

Resources mutations finish before state export.

The resources middleware serializes mutations for each rollout attempt with an asyncio.Lock. Resources prepare closes admission, acquires each live session's lock, and exports that session after any accepted mutation releases the lock. New mutations receive 409 resources_admission_closed. The first integration does not propagate admission leases or expose separate resources-admission routes.

The RL deadline policy decides what happens to unfinished rollouts.

deadline_policy is a proposed NeMo-RL policy for a rollout that cannot reach a recoverable boundary before the absolute deadline. The default should restart only attempts whose partial state can be discarded completely. The Gym stack can retire an agent attempt and abort matching model requests. It cannot yet cancel one blocked resources mutation by rollout identity. Until that API exists, a stateful resources timeout aborts the global checkpoint. A tool with non-transactional external effects, shared mutable state, or any component that cannot prove restart safety must always abort the checkpoint rather than claim a continuation.

Ordering

Generation workers stay available during prepare.

Accepted generations must finish staging their output before Gym can drain. Pausing workers earlier would deadlock prepare. NeMo-RL may pause, checkpoint, or refit workers only after Gym commits and before the final resume.

Finalizers finish before TransferQueue is saved.

Pausing Gym does not stop an RL-side finalizer that is already writing to TransferQueue. Each finalizer publishes a completed group before clearing its staged rows. If a crash interrupts this order, recovery can run the finalizer again without stranding the group.

Each manifest is written last.

A component writes payloads to temporary names, flushes them, and renames them before writing its manifest. The actor verifies every component digest before writing gym/manifest.json. The SingleController writes training_info.json last, renames the checkpoint atomically, and flushes the parent directory. A committed participant directory never changes.

One explicit call resumes work in dependency order.

Prepare, commit, and restore leave Gym paused. After the checkpoint is published and generation workers pass validation, NemoGym.resume opens resources admission, policy model admission, relays and runtimes, parked loops, and dispatch in that order.

Durability and publication

TransferQueue snapshots are content-addressed.

Each snapshot uses a fresh path and is restored by the digest recorded in the checkpoint. An interrupted save therefore cannot damage an earlier checkpoint. Restore selects the newest published checkpoint by checkpoint ID, not filesystem modification time.

Components publish immutable manifests after their payloads.

The current prototype writes one JSON payload per parked agent boundary or resources snapshot and copies token-free lineage files, then writes a digest-bearing manifest last. This makes torn writes and corrupt restore input detectable. It is not the final format for tens of thousands of live rollouts. Archive shards with a member index can replace the per-rollout files later without changing the checkpoint APIs or state machine.

Control operations are idempotent and fenced.

Every actor method and control endpoint carries checkpoint_id and an absolute deadline. Repeating a phase for the same checkpoint returns the recorded result. A stale checkpoint ID cannot reopen traffic or replace files. A short-held mutex in the NemoGym actor protects checkpoint phase changes and snapshots of the live-execution registry. It prevents two checkpoint IDs from preparing concurrently, prevents commit, abort, restore, and resume from racing, and rejects invalid transitions such as commit before prepared. The actor releases the mutex before waiting for servers to drain so checkpoint_progress and abort_checkpoint remain callable during a long prepare.

Restore

NeMo-RL chooses one recovery action for each execution.

An execution is already complete, resumes from an agent boundary, resumes from a full runtime snapshot, or starts again from its input. An execution marked transferred_to_rl cannot also have a continuation. The restored NeMo-RL registry decides whether work completed or failed. Gym does not make that decision.

Restore verifies state before dispatch.

Restore installs model lineage first, resources sessions under the new attempt second, and agent continuations last. Before dispatch begins, it checks every selected continuation against the restored TransferQueue rows. A missing row changes that rollout to a fresh dispatch. Generation workers must also report the expected policy version and pass health checks.

An opaque harness requires a full runtime snapshot.

A filesystem snapshot, sandbox identifier, or provider descriptor cannot restore an opaque harness by itself. A resumable snapshot includes the harness process tree and memory, the egress relay's pending requests and cached responses, and a provider compatibility fingerprint. At the prepare deadline, the runtime may freeze a forwarded but unfinished request as pending reissue. Restore tombstones the abandoned server-side call and sends a new request through the relay.

A rollout does not have one global state enum

The implementation deliberately separates three kinds of state. NeMo-RL owns whether a logical rollout still needs a result. The agent server owns where one /run attempt is executing. Each Gym server owns the phase of the current checkpoint transaction. Treating these as one enum would create impossible combinations: for example, an agent can be running after boundary 4 while boundary 4 is already safe to save, and a resources server can be checkpoint-prepared while the model server is still draining an accepted generation.

Logical rollout and attempt identity

rollout_id identifies the logical work across failures. attempt_index identifies one execution of that work. Restore never reactivates attempt N. It installs state for attempt N+1 and tombstones attempt N, so delayed HTTP requests from the old process receive 409 stale_attempt instead of mutating restored state.

Agent execution state

A boundary is the completed state after a whole agent turn, not a separate execution state. While the agent is running turn 5, its boundary for turn 4 may remain available as the latest safe rollback point. Prepare changes running to park_requested. The agent finishes the current operation and commits the next boundary before it blocks on an in-memory event. No file is polled on each turn.

If the deadline expires while an agent is still between boundaries, prepare fails without caching a successful result. The RL controller may retire that attempt, which cancels its task, then retry prepare. Commit includes only parked executions with a boundary. A terminal turn is not published as a continuation because its resources session has already been retired.

Checkpoint phase and admission state

The control fence is per server process and per checkpoint ID. It prevents a stale or concurrent controller from committing, restoring, or resuming the wrong transaction. Repeating the same successful operation returns its recorded result. A failed operation returns the fence to its entry phase, so the caller can retry or abandon the global checkpoint.

Admission is a separate state machine. The policy model server changes from accepting to draining when prepare closes its gate. Requests already admitted remain counted until their complete HTTP response has been sent and token custody has been recorded. When that count reaches zero, the limiter changes to paused. New requests receive 409 checkpoint_parked. Resume reopens admission after commit or restore.

The implemented recovery rule

A rollout can continue only when all required pieces agree: the agent has a nonterminal committed boundary, every stateful resources server has the matching session revision, the model ledger has the referenced call lineage, and NeMo-RL restores the corresponding TransferQueue rows. If any required piece is absent, NeMo-RL must start a replacement attempt from the original input. The Gym APIs preserve and report component state; the companion RL code chooses the final per-rollout disposition.

Prototype gaps to close before the RL integration is production-ready

  • Wire the multi-worker coordinator into Gym process startup and route one authenticated control URL per server instance. Until then, require num_workers=1.
  • Aggregate model-ledger commit and restore across the same worker set. The current coordinator protocol covers admission state and in-flight counts only.
  • Make agent retire persist a tombstone even when the retired attempt has no boundary in the checkpoint. Today it cancels the task, but a delayed duplicate /run is not independently fenced by that retirement.
  • Add identity-aware cancellation or an explicit non-restartable result for a resources mutation that holds its session lock past the deadline.
  • Make failed model restore recoverable. Restore closes model admission before installing lineage, but a failed restore returns the control fence to idle and the single-worker model resume route does not currently accept idle.
  • Apply deadline_ts inside commit, restore, and resume operations. Those request models carry the deadline today, but only prepare and model-drain waits actively enforce it.
  • Release completed execution payloads and unused lock objects without discarding the compact tombstones needed to reject stale requests.
  • Pack per-rollout payloads into bounded archive shards before using the format at very large rollout counts.
  • Implement RL-side cross-component reconciliation before dispatching any restored continuation.

How the components share checkpoint ownership

The SingleController owns the global checkpoint transaction. The NeMo-RL NemoGym Ray actor dispatches rollouts, tracks live executions, and coordinates checkpoint calls across Gym servers. The agent server owns each /run loop. The Gym model server admits policy generations and records token-free custody data, while generation workers stage token data in TransferQueue. Resources servers own tools, verifiers, and per-rollout environment state. Judge and simulator models use separate model-server instances so they remain available while policy traffic drains.

Normal rollout execution records restorable state

Each component records the state it already owns during normal execution. The actor registers executions, the model server records token custody, generation workers stage tokens, and resources servers retain sessions. Checkpointing does not add per-rollout filesystem writes during this phase. Use the controls below to follow the calls in execution order. When the walkthrough has focus, the left and right arrow keys change steps.

Prepare stops new work and reaches a recoverable boundary

The companion NeMo-RL flow first stops new /run dispatch and asks each whitebox agent server to prepare. Active runs finish their current turn and park after committing a boundary. It then pauses policy-model admission and prepares resources state. Generation workers, judges, and simulators remain available while the current turn finishes. If an agent misses the deadline, the prepare call fails. NeMo-RL may retire a restart-safe attempt and retry, but Gym does not silently discard it.

Save publishes only a complete checkpoint

The SingleController stops changes to the rollout registry and TransferQueue, then gives the Gym actor an owned checkpoint directory. Each Gym component writes its frozen state under that directory and publishes a digest-bearing manifest last. The SingleController publishes the global checkpoint only after every participant has committed, and Gym remains paused until an explicit resume. The current prototype uses per-rollout JSON and lineage files; shard packing is a later scalability optimization.

Restore verifies each continuation before dispatch

Gym starts in a paused state. Restore installs model lineage first, resources sessions second, and agent continuations last. It checks each selected continuation against the restored TransferQueue rows before dispatch can begin. The same ordered resume used after saving then reopens the system.

Why component-owned boundaries are the default

The central constraint is not writing bytes to disk. It is choosing a point where the agent conversation, resources state, model-call lineage, and token rows describe the same completed work. The proposed APIs let each component finish the operation it understands, then freeze the state it owns. NeMo-RL coordinates those participants but does not need to understand every environment's internal representation.

Normal-path cleanup still needs a production pass

The prototype retains completed agent execution objects, per-session resource lock objects, and each model limiter's set of seen attempts for the life of the server process. Those collections make checkpoint membership and stale-attempt fencing easy to validate, but their memory follows total attempts rather than only live attempts. Before enabling checkpointing for long-lived services or very large batches, the stack needs explicit retirement rules that preserve tombstones and required lineage while releasing completed execution payloads and unused locks.

Why this approach fits Gym

Gym already separates ownership across agent, model, and resources servers. The participant approach follows that boundary: shared infrastructure supplies identity, fencing, admission, manifest-last publication, and stale-attempt rejection, while each stateful implementation supplies only its codec and turn boundary. It preserves cheap drain-or-restart fallbacks, adds continuation one component at a time, and lets NeMo-RL coordinate the global checkpoint without importing environment-specific logic. The cost is more protocol surface and careful failure ordering. That cost is justified for expensive, long-running, stateful whitebox rollouts. Short stateless rollouts and opaque unsupported harnesses should continue to drain or restart.

Assumptions the controller must enforce

  • Cross-component validation is an RL responsibility. Gym records last_committed_model_call_id and resource_state_revisions, but it does not join them to restored model-ledger rows, resources snapshots, and TransferQueue rows by itself.
  • The global commit marker is outside Gym. One Gym component can commit before another fails. The SingleController must select a checkpoint only after every required participant manifest validates.
  • Deadlines use synchronized wall clocks. Every request carries one absolute deadline_ts. Excessive clock skew can shorten or extend a participant's effective budget.
  • Only bounded waits enforce the deadline in the current stack. Prepare and model-drain paths consult deadline_ts. Component commit, restore, and resume still need explicit checks around potentially long filesystem or backend operations.
  • Checkpoint paths identify the same storage namespace. Server processes must see the controller-provided directory consistently. A remote or differently mounted worker cannot interpret a process-local path.
  • An unsuccessful mutation must not hide a committed effect. The resources middleware increments revisions only for successful HTTP responses. An environment that mutates state and then returns an error needs rollback or an explicit outcome record before it can claim continuation support.
  • Atomic resources activation is an environment callback contract. The shared participant passes the complete replacement set to restore_checkpoint_states. Each adapter must validate everything before replacing live maps; the framework cannot make a sequence of arbitrary environment mutations atomic on its own.
  • Completed results cross an acknowledged ownership boundary. Agent checkpoints omit completed executions. NeMo-RL must durably accept the result before Gym removes it from the recoverable live set.
  • Capability discovery is necessary but not sufficient. A custom whitebox agent must actually call commit_boundary; inheriting checkpoint routes without emitting boundaries does not make it resumable.

APIs required to coordinate the checkpoint

The checkpoint API is delivered in four additive milestones. Each milestone produces a useful recovery guarantee and becomes the foundation for the next one. Exists means the behavior is on the main branch. PR means the Gym checkpoint stack ending at #2946 contains the behavior. New means it still needs to be built.

The SingleController calls the NemoGym actor. The actor calls Gym control endpoints, and agents call resources servers. This boundary keeps checkpoint coordination out of individual rollout implementations.

Scope of the current Gym stack

PRs #2939 through #2946 implement stable execution identity, shared fenced control contracts, single-worker policy-model admission, the multi-worker coordinator protocol and test harness, model-ledger commit and restore, whitebox agent boundaries, resources snapshots, and three environment adapters. Companion NeMo-RL orchestration is intentionally outside this stack. Production launcher wiring for the multi-worker coordinator and blackbox runtime snapshots are also outside it.

Milestone 1 — Preserve captured tokens for stateless rollouts

This milestone supports direct-answer or otherwise restartable rollouts whose resources server and verifier retain no session state. It preserves exact token rows and their model-call lineage after they reach durable custody. It does not resume inside an unfinished generation and it does not serialize an agent loop. A rollout that has not returned its result to NeMo-RL at the checkpoint boundary starts again from its original input after restore.

How each Gym server can recover

The shared APIs are not enough for servers that keep rollout state. Each concrete server needs one recovery disposition:

  • no_op: the server has no checkpoint state and needs only shared admission middleware.
  • export_restore: the server implements versioned state encoding and restoration hooks.
  • reconnect_descriptor: the server reconnects to sandbox-backed state through a ConnectableProvider.
  • restart_only: the server cannot restore a valid continuation, so the rollout starts again from its input.
  • full_runtime_snapshot: the provider captures and restores an opaque agent runtime.

The following audit covers every directory under responses_api_agents/ and resources_servers/.

Count summary

The audit covers 153 concrete servers: 40 agents and 113 resources servers.

Among the agents, 17 need no checkpoint-specific state, 5 reconnect through a descriptor, 5 require a full runtime snapshot, and 13 restart from input. Among resources servers, 93 are stateless for checkpointing, 13 export and restore state, 3 reconnect through a descriptor, and 4 restart from input.

About 34 resources servers call a judge during verification, and 2 call a simulator during environment steps. These calls do not require per-server checkpoint code when they target auxiliary model instances. Those instances remain open while the policy model instance is paused.

Session-state hooks currently exist in blackjack, example_session_state_mgmt, and workplace_assistant. gymnasium_agent also has partial agent-side resume configuration.

Recommended implementation order

  1. gymnasium base-class hook — one change covers the whole gymnasium family and gives non-exportable subclasses a declaration point.
  2. swebench reconnect descriptor — unblocks the SWE rollout class end to end; litmus_agent follows the same pattern.
  3. toolsandbox codec — serialize its DataFrames and role-scoped state by following the existing workplace_assistant pattern.
  4. The blackbox cluster (anyswe, anyterminal, harbor, osworld, swe_agents) — full-runtime snapshot through one provider, restart_only until then.
  5. The CLI-agent cluster (8 agents, one shape) — a single workspace-archive + session-file strategy later; restart_only now.
  6. aviary reconnect-by-env-id with its upstream server.

Merge milestones

Each milestone has its own recovery guarantee and validation boundary. A later milestone adds state without weakening the behavior established by an earlier one.

Milestone 1 — Token-capture checkpointing for stateless rollouts

  1. Merge unconditional rollout and attempt identity propagation.
  2. Merge the worker-owned token staging, model custody ledger, terminal attribution, and NeMo-RL finalizer stack.
  3. Add the NemoGym live-execution registry and checkpoint participant methods. In this milestone every nonterminal execution restores as fresh_dispatch.
  4. Add service-wide policy model admission, including multi-worker coordination, bounded drain, capture-ledger commit and restore, and call-root tombstones.
  5. Checkpoint TransferQueue after RL-side finalizers quiesce, then reconcile restored model manifests against the restored staging rows.
  6. Require resources servers and verifiers in this milestone to declare stateless. Do not add resources state or agent-boundary APIs yet.

Exit condition: completed captured rollouts and groups survive a controller restart with the same exact token rows. An unfinished rollout restarts from input without selecting staged rows from its abandoned attempt.

Milestone 2 — Whitebox agent continuation

  1. Add the agent-server in-memory park coordinator and checks before every model, tool, and verification operation.
  2. Add agent checkpoint prepare, commit, restore, resume, and retire.
  3. Add versioned boundary export and restore to supported Gym-native agents.
  4. Reconcile the boundary's last model-call ID with model custody and restored TransferQueue rows before making the continuation runnable.

Exit condition: a supported multi-turn whitebox agent resumes between operations with its conversation and control-flow state intact while using a stateless resources server.

Milestone 3 — Stateful resources-server continuation

  1. Add service-wide resources admission and multi-worker aggregation.
  2. Add the per-attempt session registry, stale-attempt fencing, retirement, and declared concurrency modes.
  3. Add versioned session-state export and restore hooks to the resources-server base and implement them in selected environments.
  4. Require nested judge and simulator calls to use auxiliary model instances that remain available during policy-model prepare.
  5. Apply the deadline policy only to sessions whose implementation declares that its partial state and external effects can be discarded safely.

Exit condition: a whitebox agent and its logical environment session restore under a replacement attempt. The resources state is installed before the agent resumes.

Milestone 4 — Blackbox runtime continuation

  1. Add a checkpoint-aware egress relay inside the runtime boundary.
  2. Add one runtime provider that can freeze and restore the complete harness process tree and memory.
  3. Capture pending requests and cached responses, then remap endpoints and attempt identity before resume.
  4. Keep providers without full-runtime support explicitly restart_only.

Exit condition: an opaque harness resumes from a full runtime snapshot without losing, duplicating, or misattributing a model or resources request.

Validation applied at every milestone

Inject crashes before and after every manifest publication boundary. Exercise stale checkpoint IDs, prepare deadlines, worker loss, and tens of thousands of live executions. Verify that a continuation is selected only when its agent, resources, model-custody, and TransferQueue links required by that milestone are all present.
