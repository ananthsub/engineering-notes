Partial-rollout checkpointing for NeMo-RL and NeMo Gym

owner ansubramania · revision r2026-08-27-b3e2 · supersedes r2026-08-26-f5a1 · self-contained HTML, inline CSS/JS/SVG

NeMo-RL's SingleController coordinates one checkpoint across the policy trainer, TransferQueue, its rollout registry, and NeMo Gym, which presents one checkpoint participant. This revision restates the design around the audited sequence: invariants first, then the overview, then an interactive walkthrough of every call in all four phases — runtime, prepare, save, restore — then the complete API catalogue by component level, and the per-implementation audit of every concrete Gym server. Generation workers write token deltas to TransferQueue (staged mode) throughout.

00 · Requirements and invariants

Everything else in this document derives from these. An implementation is correct exactly when every statement here holds; the walkthrough tabs show where each is exercised.

Hard requirements (given)

  • Gym is a mandatory participant. If Gym cannot commit its participant state, the SingleController cannot publish a global checkpoint. Consequence: checkpoint liveness is a first-class property — no single rollout may be able to block checkpointing indefinitely.
  • Staged-mode data plane. Generation workers stage token, mask, and logprob deltas to TransferQueue synchronously before acking each call; the Gym model server keeps a token-free custody ledger. Token arrays never transit Gym.
  • Recovery granularity is the published checkpoint. Gym server state is in-memory between checkpoints and is serialized only at commit. An unplanned crash loses all in-flight continuations back to the last published checkpoint; NeMo-RL's restored registry re-dispatches them from input. This is a stated trade, not an accident.
  • Exactly one SingleController is alive, enforced by a lease; it is the only dispatcher and the only checkpoint coordinator.
  • Scale target: tens of thousands of live executions per run; checkpoint cost must not scale in filesystem metadata operations with rollout count.

Identity

I1 — Stable rollout identity, incrementing attempts.

rollout_id is assigned by NeMo-RL before dispatch and never changes across retries or restores. Every fresh dispatch or restore increments _ng_attempt_index. The attempt-qualified transport path (…-aN) is a capture key, never the logical identity. Every artifact, control call, and result carries both fields separately.

I2 — Stale attempts are fenced everywhere.

Every model, resources, and runtime mutation carrying a superseded attempt index receives 409. Tombstones over abandoned call roots are monotonic: restore may add one, never remove or reassign one. Final attribution never selects a tombstoned root.

Admission and quiescence

I3 — Closing a gate and testing admission are one atomic operation.

The AdmissionLimiter grants a capacity permit only while accepting and atomically rejects or parks callers when closed. A capacity waiter holds no permit and is not inflight. An admitted request stays inflight until its response and its required durable custody updates complete.

I4 — Pause is scoped by instance role.

Prepare gates the policy model-server instances (the ones backed by NeMo-RL generation workers) and all resources servers. Judge and simulator model-server instances are never gated. Environment-plane traffic must not target a policy instance — validated at spinup; a plane header exempts the residual case.

I5 — Lease propagation.

The drain blocks new top-level operations only. Any request carrying the admission lease of an already-accepted operation — a tool's inner simulator call, a verify's judge call, a nested tool — is admissible, because the drain exists to let accepted operations finish.

I6 — Parkable callers are parked, never blocked.

A gated request from a parkable caller receives 409 checkpoint_parked; the agent records next_operation and parks. The agent checks the park flag before every operation — model call, tool call, and verify. Blocked waiters are reserved for callers that cannot park.

I7 — The deadline sacrifices rollouts, never the checkpoint.

An execution still draining at the deadline is force-closed: marked fresh_dispatch, its call roots tombstoned, its state discarded. Prepare succeeds with a casualty list. A global abort is reserved for infrastructure failure, not slow rollouts.

Ordering

I8 — Generation workers stay up through prepare.

Accepted generations must finish staging and release; pausing workers before Gym drains deadlocks prepare. Workers may be paused, checkpointed, or refit only in the window between Gym's commit and the final resume.

I9 — Finalizations drain before the TransferQueue save, and finalizers publish before they clear.

Finalizers write TransferQueue; pausing Gym does not stop one already running. A snapshot between clear and publish strands the group forever; publish-before-clear makes a torn snapshot re-runnable.

I10 — Manifest-last, everywhere.

Each component writes payloads to temporary names, fsyncs, renames, then writes its component manifest last. The actor verifies every digest before writing gym/manifest.json last. The SingleController writes training_info.json last, renames atomically, and fsyncs the parent. A committed participant directory is immutable.

I11 — Activation is explicit and ordered.

Prepare, commit, and restore all leave Gym paused. Only NemoGym.resume — issued after publication and generation-worker validation — opens the world, in order: resources admission, then policy model admission, then relays and runtimes, then parked loops, then dispatch.

Durability and publication

I12 — Content-addressed snapshots, ID-ordered selection.

TransferQueue snapshots write to fresh paths and are loaded by the digest the checkpoint binds — a crash mid-save can never corrupt the previous checkpoint. Restore selects the newest published checkpoint by checkpoint ID, never by mtime.

I13 — Archive-stream commits.

Component commits serialize frozen state directly into compressed archive shards with a member index (rollout → shard, offset, length) — per-rollout files are never materialized on the shared filesystem. Archives are immutable; retention keeps the last K published checkpoints wholesale.

I14 — Idempotent, fenced control.

Every actor method and control endpoint carries checkpoint_id and an absolute deadline. Repeating a call for the same ID and phase returns the recorded result. A stale checkpoint ID can neither reopen traffic nor replace files. The actor's checkpoint lock serializes transitions.

Restore

I15 — One disposition per execution, RL authoritative for completion.

Each saved execution resolves to exactly one action: completion already accepted by NeMo-RL, resume from an agent boundary, resume from a full runtime snapshot, or fresh dispatch. transferred_to_rl excludes any continuation. NeMo-RL's restored registry decides completion and failure; Gym's package never does.

I16 — Verify before dispatch.

Restore installs model lineage first, then resources sessions under the new attempt, then agent continuations; every selected chain is verified against restored TransferQueue rows before any dispatch, demoting to fresh dispatch on a miss. Workers are validated for health and policy version before resume.

I17 — Blackbox resumes only from a full runtime snapshot.

A filesystem snapshot, a sandbox identifier, or provider metadata cannot resume an opaque harness. The snapshot includes the harness process tree and memory, the egress relay's pending requests and cached responses, and a provider compatibility fingerprint. At the deadline a runtime may freeze with a forwarded-but-unfinished request marked pending-reissue: the abandoned server-side call is tombstoned and the relay re-issues it after restore.

01 · Overview

Component ownership is unchanged from the prior revision: the SingleController owns the global transaction; the NeMo-RL NemoGym Ray actor owns dispatch, the live-execution registry, and checkpoint fan-out; the agent server owns /run and the loop; every training generation passes through the Gym model server's admission gate and token-free custody ledger; tools, verifiers, and per-rollout environment state live behind resources servers; generation workers stage tokens to TransferQueue. Judge and simulator models run on their own model-server instances, separate from the policy instance — that separation is load-bearing (invariant I4).

What changed in this revision (vs r2026-08-26-f5a1)

  • Deadline semantics inverted: prepare no longer aborts the global checkpoint when a request outlives the deadline — it sacrifices the offending rollouts and succeeds with a casualty list (I7). The prior abort-only rule let one stuck tool call block checkpointing forever, which the mandatory-participant requirement cannot tolerate.
  • Instance-scoped pause (I4) and lease propagation (I5): judge and simulator model instances are never gated, and nested calls under an accepted lease always flow. This removes the two prepare deadlocks: a verify's judge call, and a simulator call inside a draining tool.
  • Verify is a parkable operation and gated parkable callers receive checkpoint_parked (I6) — no stuck waiters, no completion-through-closed-gates ambiguity.
  • Worker ordering pinned (I8): generation workers stay up through prepare; the pause window is between commit and resume.
  • Finalizer drain before the TransferQueue save; publish-before-clear (I9).
  • Blackbox pending-reissue freeze (I17): a runtime can freeze at the deadline without waiting for a pathological generation; the abandoned call is tombstoned and re-issued after restore.
  • Archive-stream commits (I13): component dumps serialize directly into compressed shards with a member index — no per-rollout small files on the shared filesystem.
  • Live-execution registry gains a phase field (queued → issued → running → parked | transferred); registration happens before the concurrency semaphore, so rollouts dispatched but never started are classified correctly.
  • Long-poll status endpoints; content-addressed TransferQueue snapshots loaded by bound digest; checkpoint selection by ID.

02 · Runtime — business as usual

Every artifact a checkpoint needs is produced here by its normal owner: the actor registers executions, the model server keeps its custody ledger, workers stage tokens, resources servers hold sessions. Nothing extra is written for checkpointing during runtime — the design saves in-memory state at commit. Step through each call; arrow keys work when a stepper is focused.

03 · Prepare — park, drain, sacrifice

Prepare is a synchronization barrier: it stops new work, lets accepted operations finish, parks every loop at a restorable point, and freezes blackbox runtimes. Its deadline sacrifices individual rollouts, never the checkpoint (I7). Generation workers keep serving throughout (I8); judge and simulator instances are never gated (I4).

04 · Save — seal, commit, publish, resume

The SingleController seals its data plane, hands the actor an owned directory, and publishes only after every participant commits. Everything stays paused until one explicit resume (I11). Gym state streams into archive shards — no per-rollout files touch the shared filesystem (I13).

05 · Restore — install, verify, resume

Restore installs state with everything paused, in dependency order — lineage, then sessions, then continuations — verifies every selected chain against restored TransferQueue before any dispatch (I16), and activates the world with the same ordered resume as a save.

07 · Implementation audit — every concrete server

The base-class APIs above are necessary but not sufficient: each concrete server must be classified and, where stateful, implement its typed hooks. The dispositions: no_op — stateless; the shared admission middleware is the only change. export_restore — implement the versioned state codec hooks. reconnect_descriptor — sandbox-backed resources state; resumable only on a ConnectableProvider. restart_only — no valid continuation is possible; rollouts restart from input. full_runtime_snapshot — blackbox agent runtimes. Highest-leverage work, in order

  1. gymnasium base-class hook — one change covers the whole gymnasium family and gives non-exportable subclasses a declaration point.
  2. swebench reconnect descriptor — unblocks the SWE rollout class end to end; litmus_agent follows the same pattern.
  3. toolsandbox codec — the hardest export_restore, with workplace_assistant as its proven template.
  4. The blackbox cluster (anyswe, anyterminal, harbor, osworld, swe_agents) — full-runtime snapshot through one provider, restart_only until then.
  5. The CLI-agent cluster (8 agents, one shape) — a single workspace-archive + session-file strategy later; restart_only now.
  6. aviary reconnect-by-env-id with its upstream server.

08 · Merge sequence

Each step establishes a contract the next depends on; 3a–3c can proceed in parallel once step 2 lands.

  1. Stable execution identity. Unconditional rollout_id + _ng_attempt_index propagation; the -aN transport/logical split; identity in every artifact, result, and registry entry.
  2. Live-execution registry. Pre-semaphore registration with the phase field; result-handoff acknowledgement; dispatch fencing under a checkpoint id; the participant server registry with instance roles.
  3. 3a — Model-server admission. The gate around every training generation route; plane and lease headers; call-id echo; abort_inflight; multi-process aggregation; existing token-custody ordering preserved.
  4. 3b — Resources admission and state. The gate around tool and verifier routes with lease propagation; concurrency contracts; versioned export/restore; stale-attempt 409; abort_inflight.
  5. 3c — Agent boundaries. Park-before-next-operation including verify; checkpoint_parked handling; per-attempt single-flight; versioned export_boundary; restore under a new attempt; the status route with blocking-operation diagnosis.
  6. 4 — The participant. The five actor verbs plus checkpoint_progress; the archive writer; capability negotiation; manifest discipline.
  7. 5 — SingleController integration. Two-phase with sacrifice-not-abort; finalizer drain before the TQ save; content-addressed TQ snapshots; publish-then-validate-workers-then-resume; abort on any pre-publish failure.
  8. 6 — Gym-native end-to-end recovery. Restore ordering; chain-versus-TransferQueue verification before dispatch; attempt allocation and tombstones; attribution verified across crashes.
  9. 7 — Blackbox continuation. Egress relay; one full-runtime provider; pending-reissue; restart-from-input fallback for every other provider.
  10. 8 — Scale and fault validation. Tens of thousands of live executions; pathologically long generations and tools exercising the sacrifice path; aborts and process kills at every save boundary; stale checkpoint ids; restore attribution; shared-filesystem metadata load under the archive writer.
