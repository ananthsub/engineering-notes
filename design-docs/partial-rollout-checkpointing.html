Partial-rollout checkpointing for NeMo-RL and NeMo Gym

NeMo-RL’s SingleController coordinates one checkpoint across the policy trainer, TransferQueue, rollout registry, and NeMo Gym. Gym presents one checkpoint participant to SingleController. Inside Gym, the agent server owns the rollout loop, every generation request passes through the Gym model server, and tools and verifier state live behind resources servers. This proposal defines how those components stop new work, drain accepted requests, save state, and restore an incomplete rollout.

Required orderingSingleController saves the TransferQueue and pending/inflight rollout state, then asks the NemoGym actor to commit its participant package. Each Gym server dumps its own state into the supplied subdirectory. Actor dispatch and Gym components remain paused after commit. SingleController publishes the global checkpoint, resumes and validates generation workers, and then explicitly calls NemoGym.resume.
Two NeMo-RL registries with different responsibilitiesThe rollout manager and data-plane registry own pending work, GRPO group membership, received results, retry decisions, and training consumption. The NemoGym actor’s proposed live-execution registry tracks only agent /run calls that the actor currently owns. SingleController does not copy the rollout registry into the actor or send a rollout list during prepare. Restore reconciles the two registries through stable rollout IDs.

Terms used in this proposal

Trainer anchor

The policy model, optimizer, scheduler, and trainer step that SingleController saves together. Restored rollout data must be compatible with this model state.

Data-plane cut

The exact TransferQueue contents and NeMo-RL pending/inflight rollout state included in one checkpoint. “Sealed” means later updates cannot enter that saved copy.

Quiesce

First close admission so no new request can enter. Then allow already accepted requests to finish while queued callers remain blocked. A model or resources server is paused only when admission is closed and its inflight count is zero. An agent server’s long-running /run request may remain open while its agent loop is paused at a saved boundary or its blackbox runtime is frozen.

NemoGym actor live-execution registry

The NeMo-RL actor registers each (rollout_id, _ng_attempt_index) before run_examples() issues the agent request. The entry holds the request task, Gym component handles, and execution status. It remains until the actor returns the result to NeMo-RL’s rollout manager or propagates the failure. Prepare freezes current membership instead of receiving a rollout list from SingleController.

Prepared NemoGym participant state

The actor has stopped new dispatch, frozen its live-execution registry, closed both Gym server admission gates, and saved or frozen every active execution. Commit writes the actor manifest and referenced component descriptors but does not release them. The participant remains paused until SingleController calls resume or aborts the checkpoint.

Admission gate

The accepting, draining, or paused state on a model server or resources server. Middleware on each server increments a per-rollout attempt counter when it accepts a request and decrements the counter only after the response and related state are durable. The active checkpoint_id owns a closed gate.

Active rollouts, active runs, and inflight requests

NemoGym.active_rollouts are registered rollout executions. An agent server’s active_runs are /run handlers holding concurrency permits; they remain active while parked. Only model-generation and resources-server requests use inflight, and those shorter requests drain to zero during prepare.

run_task

The in-memory future or asyncio.Task for one agent /run request. Today run_examples() returns these futures through tqdm.as_completed(). The proposed actor registry keeps the task only for runtime control. It is not stable across actor restart and is never serialized into the checkpoint package.

Resources-request counters

The proposed resources admission layer keeps one server-wide inflight count and optional diagnostic counts keyed by (rollout_id, _ng_attempt_index). A request enters both counts after it receives an admission lease. It leaves after the endpoint response and any session-state mutation complete. These counters do not exist in the current generic resources-server base.

Parallel tool calls

Each accepted tool HTTP request counts separately. Stateless tools may execute concurrently. A stateful resources server must declare either per-session serialization or transactional parallel updates. Under per-session serialization, an admitted request waiting for the session lock remains inflight, so prepare waits for it before exporting state.

Restore action for each rollout

Complete means NeMo-RL’s restored rollout and data-plane state says the result was accepted or finalized. Resume means the NemoGym package contains valid agent/resources state or a full runtime snapshot. Restart means NeMo-RL still owns the work but no valid continuation exists.

Agent boundary

A point after the agent server has stored the latest model or resources-server response and before it issues the next request. boundary_index increases at each saved boundary. The versioned agent state says exactly what operation comes next.

Call root and tombstone

A call root identifies one chain of captured model calls. A tombstone marks a root from an abandoned attempt so training attribution cannot attach it to a restored attempt.

Completion and failure ownership

The NeMo-RL rollout manager receives streamed results from NemoGym.run_rollouts() and owns retry or terminal-failure decisions. The Gym run_examples() path does not write rollout output or failure sidecars. Model-call capture failures remain in the existing capture ledger and receipt metadata.

Result handoff boundary

An execution can be marked transferred_to_rl only after the rollout manager accepts the streamed result or typed failure into its registry. Prepare cannot acknowledge while a completed /run response is between the actor and that registry. This handoff acknowledgement is a required addition; Gym sidecar files are not a substitute.

NemoGym manifest

gym/manifest.json indexes the actor’s checkpoint package. It names the executions selected during prepare and the agent, resources, runtime, and model-lineage artifacts needed for continuation. It does not independently claim whether NeMo-RL accepted, failed, or finalized a rollout.

Full runtime snapshot

A sandbox/runtime-provider artifact that includes the blackbox harness process tree, memory, and filesystem. Its compatibility fingerprint records the provider, runtime, and format versions required to restore it. A sandbox ID or filesystem snapshot alone is insufficient.

Post-checkpoint work

Requests and state changes that occur after SingleController explicitly resumes the NemoGym participant. They belong to the next checkpoint and cannot modify the committed participant directory.

Running: artifacts are produced before anyone asks to save

Checkpointing collects state from its existing owners. NeMo-RL supplies rollout and training status. The NemoGym actor supplies active execution membership. Gym servers supply agent, environment, runtime, and model-lineage state under the same rollout and attempt keys.

step 1 /

rollout_id: one logical trajectory

NeMo-RL assigns this ID before dispatch. It stays the same when the rollout is retried or restored. A GRPO group contains several rollout IDs, one for each sibling trajectory.

_ng_attempt_index: one execution lineage

Gym already stamps retries with an attempt index. Every fresh dispatch or restore increments it. Model calls, resource calls, snapshots, and the result returned to NeMo-RL carry the stable rollout ID and the attempt index that produced them.

checkpoint_id: one save transaction

SingleController assigns this ID to a global checkpoint. It groups trainer, TQ, registry, and Gym artifacts. It is not part of a rollout’s execution identity.

The NeMo-RL NemoGym actor tracks active /run invocationsThe actor stores the rollout and attempt IDs, active task or future, agent-server and session handles, lifecycle phase, and checkpoint references. It does not duplicate NeMo-RL’s canonical input row, pending queue, GRPO group state, or finalization state. The saved agent conversation supplies continuation state; NeMo-RL supplies the original task input when an execution must restart.
Required identity cleanupToday maybe_rollout_id_from_run_body() appends -aN to the model-call correlation path for retries. Checkpoint records must not treat that attempt-qualified path as the logical rollout ID. They store the stable rollout_id and _ng_attempt_index separately. The model server may continue to use an attempt-qualified path as a transport and capture key.

NeMo-RL determines whether an attempt ended

The rollout manager receives each streamed run_rollouts result and owns retry and terminal-failure decisions. The NemoGym actor does not convert those decisions into Gym sidecar files. Final model-call attribution uses the existing capture ledger and ignores call roots from abandoned attempts.

Gym saves agent boundaries after both servers drain

A Gym-native agent reaches a checkpoint boundary after it has appended the latest model response or resources-server result to its conversation state. NemoGym closes both admission gates and confirms that each server’s aggregate inflight count is zero before exporting boundaries from parked agent runs.

Current and required tool-call behaviorThe current simple_agent iterates over returned function calls and awaits each resources request in order. The API can still represent parallel tool calls, and blackbox or future agents may issue them concurrently. Checkpoint correctness therefore cannot rely on agent-side serialization. Stateful resources servers must serialize mutations per session by default or implement an explicit transactional concurrency contract.

Prepare: stop at restorable boundaries without finishing rollouts

prepare_checkpoint is a synchronization barrier. It stops new rollout dispatch, lets only the model and resources requests that were already accepted finish, and parks each agent before its next operation. Its successful return only acknowledges that Gym is paused at restorable boundaries. SingleController then saves the TransferQueue and pending/inflight rollout registry before asking Gym to write into the checkpoint directory.

The Gym model server and each stateful resources server implement the same admission states. They keep separate inflight and waiter counts because model generation and resource calls drain independently.

Admission and capacity are one operationA checkpoint-aware AdmissionLimiter replaces a separate “check paused, then acquire semaphore” sequence. It atomically rejects or queues a caller when admission is closed and grants a capacity permit only while accepting. A capacity waiter has no permit and is not inflight. After admission, a stateful tool request waiting for its per-session lock is inflight because it must complete before the session can be exported. An admitted request remains inflight until its response and required state or custody updates complete.
The rollout does not finish during prepareThe inflight counters cover individual generation and resources-server requests. They do not count the agent server’s long-running /run request. Gym waits for an already accepted generation or resource operation to finish, records its response, and parks the agent before the next operation. All earlier turns remain saved. Continuing a partially generated token stream is outside this proposal.
Drain deadlineThe pause endpoint closes admission immediately and returns draining. NemoGym polls model-server and resources-server status using the absolute deadline supplied to prepare_checkpoint. Each HTTP call uses the remaining time as its client timeout. If either accepted-request count is still nonzero at the deadline, prepare fails and SingleController aborts the global checkpoint.
draining is progress, not saved stateThe checkpoint requires closed admission and zero accepted requests, but it does not require a durable draining record. The status lets NemoGym observe progress, retry control calls idempotently, and enforce the deadline without holding one long HTTP request. A blocking server prepare method could provide the same safety guarantee.
A prepare failure aborts the checkpointIf a model or resources request does not finish before the deadline, prepare_checkpoint returns an error. SingleController aborts the entire global checkpoint and tells every participant, including Gym, to resume. No partial global checkpoint is published.

Checkpoint state transitions

The participant and each Gym server retain their prepared in-memory state until commit writes it. A successful component write changes the component checkpoint phase to committed_paused; it does not reopen admission or release an agent loop. For model and resources servers, admission remains paused throughout the frozen, writing, and committed checkpoint phases.

step 1 /

Save: commit Gym while paused, publish, then resume

After the NemoGym actor acknowledges preparation, SingleController saves TransferQueue and its pending/inflight rollout registry. It then supplies the actor’s gym/ directory. The actor gives each Gym server its own subdirectory. Each server serializes the in-memory state it owns and returns a descriptor. The actor writes its live-execution records and top-level manifest last, then returns committed_paused.

step 1 /

Resources server dumps session state

  1. Prepare closes tool and verifier admission.
  2. Every admitted handler and per-session lock waiter completes.
  3. The server freezes its registry of active (rollout_id, _ng_attempt_index) sessions.
  4. Commit serializes each supported session through the environment’s versioned state codec into resources/<server>/sessions/.
  5. The server fsyncs payloads, writes its component manifest last, and returns its path, digest, schema versions, and session count.

In-memory state is not assumed durable before this write. Stateless servers return an empty-state descriptor.

Agent server dumps parked run state

  1. Prepare marks every active run to pause after its current model or resource operation.
  2. Each Gym-native loop parks after appending the completed response and recording next_operation.
  3. Commit serializes the conversation and explicit control fields into agents/<agent>/runs/.
  4. The agent server writes its component manifest last and returns its descriptor.
  5. A blackbox agent records a runtime-provider snapshot descriptor instead of logical loop state.

The in-memory coroutine, Python stack, HTTP socket, and run_task are not serialized.

Each component publishes its subdirectory atomicallyA component writes payloads to temporary names, fsyncs them, atomically renames them to final names, then writes and fsyncs its component manifest last. The NemoGym actor verifies every returned manifest digest before writing gym/manifest.json. Repeating commit for the same checkpoint ID verifies and returns the same descriptor instead of rewriting live state.
The directory must be writable from each server processThe direct-dump path assumes the controller checkpoint filesystem is mounted into the NemoGym actor and Gym server processes. If a component runs on a node without that mount, the same component hook writes through a checkpoint-writer abstraction backed by shared object storage. Large session or runtime payloads should not be returned through the control-plane HTTP response.
Only SingleController activates the participantcommit_checkpoint writes the actor package but leaves actor dispatch, Gym model admission, Gym resources admission, and agent loops paused. After publication and generation-worker readiness checks, NemoGym.resume opens resources admission, opens model admission, releases parked agent loops, and finally allows new actor dispatch.

Restore: choose an action for each rollout from saved records

NeMo-RL restores its rollout registry, TransferQueue, replay state, and finalization state before reconciling active Gym executions. A rollout already accepted or finalized by NeMo-RL is complete. A rollout still owned by NeMo-RL resumes from a valid NemoGym continuation or restarts from its task input. The Gym rollout helper contributes no output or failure sidecar to this decision.

Transcript replay can duplicate or change tool effectsA tool may read the current clock, consume a queue item, update a remote repository, run against a changed service, or sample randomness. Reissuing it can produce a different observation or duplicate a side effect. Replay remains useful only for components with an explicit deterministic/idempotent contract; it is not the default rollout recovery path.

Blackbox path: snapshot the runtime, not just its files

For a blackbox agent, the agent server launches an opaque harness inside a managed runtime but cannot inspect the harness loop. A checkpoint-aware egress relay inside that runtime carries model and resources requests to the external Gym servers. During prepare, the relay stops forwarding new requests while already accepted server requests drain. Requests still local to the relay and responses not yet consumed by the harness are captured with the runtime. The relay is not the Gym model server; the model server remains a shared external service.

Proposed checkpoint APIs

SingleController calls methods on the NeMo-RL NemoGym Ray actor. Prepare fences actor dispatch and snapshots the actor’s live-execution registry; it does not send a list of rollout IDs. Commit supplies the actor-owned gym/ participant directory inside the controller’s temporary checkpoint. Restore loads that directory while actor dispatch and Gym server admission remain paused, and a separate resume activates it after every participant is ready.

Primary SingleController interfaceThese are actor calls, not HTTP calls. SingleController holds the NemoGym Ray actor and invokes prepare_checkpoint, commit_checkpoint, abort_checkpoint, restore_checkpoint, and resume. HTTP-shaped JSON below illustrates payloads exchanged among Gym servers. SingleController does not call those server endpoints directly.

Current startup objects

NemoGym._spinup() starts Gym through RunHelper, stores the head-server address, and creates RolloutCollectionHelper. Today run_rollouts() calls run_examples(), whose ServerClient resolves an agent’s logical name to a direct host and port.

New participant registry

At spinup, the actor builds a registry from the fully resolved Gym config. Each entry contains a stable instance ID, role, logical name, direct control endpoint, configured checkpoint root, and advertised capabilities. The actor queries /ng-control/v1/capabilities and fails setup when a required component cannot checkpoint.

No first-instance shortcut

The current request path can select the first matching server configuration. Checkpointing must enumerate every concrete instance. Prepare and resume fan out to all registered instances; commit collects one descriptor from each instance. Manifests use stable instance IDs so restore cannot load state into the wrong process.

Servers identify their own local stateThe actor does not send tens of thousands of rollout IDs in control requests. Each agent server registers its local /run handlers. Each model and resources server registers requests and session state under (rollout_id, _ng_attempt_index) as normal traffic arrives. The actor records the agent-server instance used for each dispatch and pauses every configured model and resources instance. Component commit endpoints enumerate their frozen local registries.
RunHelper remains process supervisionThe actor uses RunHelper.poll() to detect dead Gym subprocesses. It uses direct server control endpoints for checkpoint state. A live process is not evidence that its admission gate, in-memory registry, or component dump is ready.
Gym model server and generation workers remain separateThe actor controls the Gym model server that owns HTTP admission and the token-free capture ledger. It does not pause or restore NeMo-RL generation workers through that HTTP control plane. SingleController controls generation-worker readiness separately and calls NemoGym.resume only after those workers are healthy and policy-compatible.

Prepare fan-out

  1. Acquire the actor checkpoint lock and close new run_rollouts dispatch.
  2. Tell every active agent server to park its local runs.
  3. Close admission on every configured model and resources-server instance concurrently.
  4. Poll each instance directly until it is paused or the shared deadline expires.
  5. Confirm agent runs and blackbox runtimes are parked, then return the Ray prepare acknowledgement.

Commit fan-out

  1. Receive the controller-owned gym/ directory through the Ray call.
  2. Create one subdirectory for each stable server instance.
  3. Call component commit endpoints concurrently with their subdirectory paths.
  4. Verify every returned component manifest and digest.
  5. Write actor execution records and gym/manifest.json last.
  6. Return committed_paused through Ray.

Restore fan-out

  1. Start or reconnect Gym server instances in paused bootstrap mode.
  2. Match component manifests to stable instance IDs and verify capabilities.
  3. Restore model lineage and resources sessions before agent continuations.
  4. Keep every server paused after its restore response.
  5. Wait for SingleController to validate generation workers before processing resume.

Failure behavior

Every control call carries checkpoint_id, an absolute deadline, and authenticated control access. A timeout, unreachable server, capability mismatch, rejected directory, or component-write failure fails the actor method. Before publication, SingleController then calls actor abort. Stale checkpoint IDs cannot change gates or files.

Cross-artifact invariants

Prepared-set coverage

Every execution selected when prepare fences dispatch has exactly one attempt.json. An execution returned to the rollout manager while accepted calls drain remains listed with transferred_to_rl; it does not carry an outcome payload.

One restore disposition

Each execution selects exactly one action: reconcile a transfer to NeMo-RL, restore an agent boundary, restore a full runtime, or request fresh dispatch. The referenced files must match that action.

Identity consistency

All records for one saved execution carry the same rollout_id and source _ng_attempt_index. Restore keeps the rollout ID, allocates the next attempt index, and records the source index.

Boundary consistency

An agent boundary and all resources snapshots it references use the same boundary_index. Resources state restores before the agent becomes runnable.

Transferred ownership excludes continuation

An execution marked transferred_to_rl has no agent or runtime continuation in this package. NeMo-RL’s restored registry is authoritative for whether that transfer became a completed result, a failure decision, or pending work.

Model-call custody

Every selected model-call lineage points to acknowledged TransferQueue staging rows with matching chained digests. Tombstoned roots are never selected.

Blackbox snapshot boundary

A full runtime descriptor is valid only after the in-runtime egress relay stops forwarding, both server gates close, and accepted requests reach zero. The snapshot includes relay state, and provider and runtime fingerprints must match at restore.

Manifest completeness

gym/manifest.json is written after all child files and objects. Its checkpoint ID, child count, and hashes must validate before Gym creates any restored execution.

Invariants and crash windows

Directory and save-order invariants

  1. Prepare returns a success acknowledgement only after every selected execution reaches a restorable boundary or transfers back to NeMo-RL.
  2. The TransferQueue and pending/inflight registry are saved before the NemoGym actor commits.
  3. The actor writes only inside the directory supplied for that checkpoint ID.
  4. A successful actor commit returns committed_paused.
  5. The committed participant directory is immutable.
  6. SingleController publishes before it resumes generation workers or the actor.
  7. Restore uses only a globally published checkpoint.

Pause and restore invariants

  1. Closing a gate and testing admission are one atomic operation.
  2. A Gym model or resources server is paused only when its admission gate is closed and inflight == 0.
  3. A Gym agent server may keep its /run request open and its concurrency permit held while the agent loop is saved or frozen.
  4. Prepare leaves actor dispatch and Gym components paused until SingleController explicitly calls resume or aborts the checkpoint.
  5. Commit success and commit failure both leave the participant paused.
  6. Abort before publication resumes the participant and cleans the temporary package.
  7. Generation workers must be healthy and policy-compatible before SingleController calls NemoGym.resume.
  8. Restore loads checkpoint_dir with actor dispatch and Gym server admission paused; separate resume opens them only after all participants are ready.
  9. No runtime snapshot starts while model-server or resources-server requests are in flight.

Merge sequence

Each step establishes a contract required by the next step. Model admission, resources admission, and Gym-native agent state can proceed in parallel after the live-execution registry lands.

first

1 · Stable execution identity

Make rollout_id available independently of observability or token capture. Store _ng_attempt_index separately in every model call, resource call, agent state, returned result, and NeMo-RL registry entry.

second

2 · NeMo-RL NemoGym live-execution registry

Register each agent /run before Gym run_examples() issues it. Add an acknowledged handoff from the actor to the rollout manager before removing a completed or failed execution. Add dispatch fencing and checkpoint membership under a checkpoint ID.

parallel after 2

3a · Gym model-server admission

Add the accepting, draining, and paused gate around every training generation route. Track aggregate and per-attempt request counts and preserve the existing token-custody ordering.

parallel after 2

3b · Resources-server admission and state

Add admission accounting around tool and verifier routes. Define versioned export, restore, and stale-attempt rejection for stateful resources servers.

parallel after 2

3c · Gym-native agent boundaries

Define pause-after-current-operation, versioned boundary export, restore under a new attempt index, and resume for Gym-native agent servers.

after 3a–3c

4 · NemoGym checkpoint participant

Implement prepare_checkpoint, commit_checkpoint, abort_checkpoint, restore_checkpoint, and resume on the NeMo-RL actor. Write its execution records and Gym component descriptors into the controller-provided directory.

after 4

5 · SingleController integration

Call NemoGym.prepare_checkpoint, save TransferQueue and the NeMo-RL registry, provide the actor’s participant directory, abort every participant on any failure, and publish only after all participant state is complete.

after 5

6 · Gym-native end-to-end recovery

Reconcile the actor package against NeMo-RL’s rollout registry, restore resources state before agent state, allocate the next attempt index, reopen admission only after global activation, and verify model-call attribution across crashes.

after Gym-native recovery

7 · Blackbox runtime continuation

Add full process-memory snapshot and restore through one runtime provider. Keep restart-from-input as the fallback for providers that cannot restore the complete harness runtime.

last gate

8 · Scale and fault validation

Exercise tens of thousands of live executions, long-running generation requests, checkpoint aborts, process failures at every save boundary, stale checkpoint IDs, and restore attribution.
